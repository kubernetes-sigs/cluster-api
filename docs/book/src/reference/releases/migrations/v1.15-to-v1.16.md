## Suggested changes for providers

- The `ClusterCache` interface in `sigs.k8s.io/cluster-api/controllers/clustercache` has a new `Connected` method, which
  returns true if there is a connection to the workload cluster; implementations of the interface (e.g. fakes in tests)
  must implement it. Consumers of the `ClusterCache` can use this method to check if a connection is available.
- `clustercache.Options.SecretClient` has been renamed to `SecretCachingClient`. The ClusterCache now reads the kubeconfig Secret
  on every reconcile of a Cluster to detect kubeconfig changes (e.g. token rotations), so the client must cache kubeconfig Secrets.
- The `rest.Config` returned by `ClusterCache.GetRESTConfig` doesn't contain the bearer token of the kubeconfig in `BearerToken`
  anymore. The token is added by a transport wrapper instead, so that token rotations are applied without re-creating the
  connection. Clients created from the `rest.Config` are not affected, but the token cannot be read from the `rest.Config` anymore.
